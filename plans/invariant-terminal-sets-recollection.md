# Plan: Recollect Deterministic Datasets with Invariant Terminal Sets

## Goal

Recollect the pendulum, cartpole, quadrotor-2D (RL), and quadrotor-3D (LQR)
deterministic datasets so that successful trajectories are **not** terminated at
first entry into the goal region. Success is instead defined by membership of
the **terminal** state in a **strictly invariant ellipsoid**, and successful
trajectories run to a fixed horizon T so their terminal states settle at the
closed-loop attractor, deep inside the ellipsoid.

## Motivation

The downstream flow-matching model predicts terminal states. In the current
datasets, successful trajectories are cut at the first state inside the goal
ball, so terminal states hug the ball boundary (measured: mean entry distance is
> 99% of the threshold in every dataset). Model approximation error pushes
predictions across the boundary, misclassifying successes.

Fix: (1) classify success with a region that is *invariant* under the closed
loop, so membership of any state — including a model-predicted one — soundly
implies task success; (2) let successful trajectories run past entry so the
recorded terminal state is the settled attractor, giving the model the full
region as error margin.

## Empirical findings that shaped the design

(Analysis scripts: session scratchpad `analyze_*_settling.py`,
`invariance_*.py`, `ellipsoid_*.py`; July 2026.)

1. **Euclidean balls are never invariant.** All four closed loops are
   non-normal; a state entering a radius-R ball transiently excurses to
   gain x R before converging (pendulum 2.6, quad2D 3.2, quad3D 4.9,
   cartpole 5.4, roughly constant in R). Enlarging the radius cannot fix this.
2. **Discrete-Lyapunov ellipsoids are invariant.** Finite-differencing the true
   closed-loop step map (PyBullet/env + controller, not the symbolic model) at
   the attractor and solving `A_d' P A_d - P = -Q` yields ellipsoids
   `{(s-s0)' P (s-s0) <= c}` that are empirically invariant under the full
   nonlinear dynamics up to a level c_max (validated by shell sampling: V never
   exceeds c beyond 0.5% numerical tolerance and all samples converge to s0).
3. **Entering the ellipsoid guarantees success**: every sampled state inside it
   converges to the attractor without leaving the state box.
4. **The failure (out-of-bounds) set cannot be made invariant.** Continuing
   simulation from first-OOB states, 21-26% re-enter the bounds and reach the
   goal (cartpole 32/150, quad2D 30/120, quad3D 31/120). OOB is failure *by
   definition* (constraint violation ends the episode); no outer margin makes it
   a dynamical trap. Failure handling therefore stays as-is.
5. **The quad2D RL policy has steady-state error**: it converges to
   (x, z) = (0.13226, 0.91547), distance 0.157 from the nominal goal (0, 1),
   for every entry tested. Its invariant set must be centered at this attractor.
6. **Noisy datasets are out of scope**: under the stochastic dynamics the state
   never settles (at `high`/`xhigh` the stationary noise floor exceeds the goal
   radius); no invariant set exists.

## Status: opt-in via `--invariant_terminal_sets` (off by default)

The scheme below is implemented in all four generators but gated behind the
`--invariant_terminal_sets` CLI flag, **off by default**. The default behavior
is the original one: trajectories terminate at (and include) the first state
inside the goal region (pendulum 0.075 L2 ball, cartpole 0.05 L2 ball, quad2D
`--goal_tolerance` ball around the nominal goal, quad3D 0.05 L2 ball), with
the original horizons and goal_reached/timeout labels. The flag switches on
the fixed-horizon + invariant-ellipsoid-label scheme; the pendulum generator
also appends `_invariant` to its default output directory in that mode.

## Design

### Success sets (strictly invariant ellipsoids)

`SUCCESS(s) := (s - s0)' P (s - s0) <= c`, evaluated on the terminal state.
All coordinates in **env order**.

| System | Center s0 | c | Per-coordinate extents |
|---|---|---|---|
| Pendulum | (0, 0) | 2.99 | theta ±0.153, theta_dot ±1.65 |
| Cartpole | (0, 0, 0, 0) | 3.0 | x ±0.92, x_dot ±2.16, theta ±0.37, theta_dot ±3.04 |
| Quad3D | hover (0,0,1), rest | 0.025 | x,y ±0.016, z ±0.016, velocities ±0.031, angles ±0.010, rates ±0.16 |
| Quad2D | attractor (0.13226, 0, 0.91547, 0, 0, 0) | 1.0 | x ±0.099, x_dot ±0.17, z ±0.093, z_dot ±0.12, theta ±0.048, theta_dot ±0.95 |

P matrices:

- Pendulum (state [theta, theta_dot], Q = diag(0.03, 1)):
  `P = [[127.5653, 0.9878], [0.9878, 1.1038]]`, c = 2.99.
- Cartpole (state [x, x_dot, theta, theta_dot], Q = diag(1/6^2, 1/5^2, 1, 1/5^2)):
  `P = [[5.6113, 3.60452, 10.04434, 2.7045], [3.60452, 6.22199, 17.72571, 4.78897],
  [10.04434, 17.72571, 82.27944, 15.88632], [2.7045, 4.78897, 15.88632, 4.16896]]`, c = 3.0.
- Quad3D (12-dim env order, Q = I): c = 0.025 (validation with denser shell
  sampling reduced the level from 0.1). P regenerated by script (see below).
- Quad2D (6-dim env order, Q = I, FD at the attractor): c = 1.0. P regenerated by script.

A new script `compute_invariant_sets.py` (repo root) recomputes all four
(A_d by central finite differences of the true closed-loop step, eps = 1e-4;
`scipy.linalg.solve_discrete_lyapunov`; level validation by shell sampling) and
writes artifacts `invariant_sets/<system>.npz` (fields: `P`, `center`, `c`,
`state_order`, `Q_shaping`, validation metadata). Artifacts are checked in;
generators load them.

Notes:
- Pendulum/cartpole: old success balls are strictly contained in the new
  ellipsoids (labels can only flip timeout->success). Quad3D/quad2D sets are not
  supersets of the old balls; success rates will shift.
- Quad3D margins are the tightest (angles ±0.010, positions ±0.016). If model
  error exceeds this, revisit the Q shaping (trade rate margin, ±0.16 vs
  bound 24, for angle/position margin).

### Termination rules (collection)

- **Failure**: unchanged — terminate at first out-of-bounds state (Euclidean
  dims only, angles never terminate). Terminal state is the first OOB state.
- **No goal termination.** Trajectories that never go OOB run to the fixed
  horizon T. Success label = terminal state in the ellipsoid (equivalent, by
  invariance, to "ever entered").
- **Fixed horizons** (steps at 100 Hz), sized as (old max success length) +
  settle buffer from the measured V-contraction rate:

| Dataset | Old max success length | T |
|---|---|---|
| pendulum LQR | 502 | 600 |
| pendulum RL (v*_strong/weak) | ~1000 | 1100 |
| cartpole | 613 | 700 |
| quad3D LQR | 636 | 800 |
| quad2D RL | 1200 (cap) | 1500 |

- Pendulum has no OOB (theta wraps, theta_dot clips): all trajectories have
  exactly T+1 states; label by terminal ellipsoid membership.

### Post-collection validation

- Report the distribution of terminal `V/c` over successful trajectories; a
  tail near 1 indicates late arrivals -> bump T and resume (generators are
  resumable).
- Verify achieved-bounds closure as before (only failed terminal states exceed
  bounds).
- Success-rate sanity check against the old datasets (pendulum/cartpole must
  have success_rate_new >= success_rate_old since sets grew).

### Dataset outputs

Same formats/locations as the existing deterministic datasets (new sibling
directories, do not overwrite):
`.../deterministic/<name>_invariant/` with `trajectories/sequence_<i>.txt`,
`roa_labels.txt`, `dataset_description.json`. The description gains an
`invariant_set` section (P, center, c, state order, validation evidence,
generation provenance) and records T and the termination rules.

### Script changes

1. `generate_inverted_pendulum_trajectories.py`: drop `done` -> success
   termination; run exactly T steps; label by terminal ellipsoid membership
   (load artifact). Applies to both LQR and RL controllers.
2. `generate_cartpole_trajectories.py`: keep OOB termination; remove
   goal-reached termination by passing
   `task_info={'stabilization_goal_tolerance': 0.0}` (goal_reached then never
   fires, and `_get_done` falls through to the OOB check, which also sets
   `out_of_bounds` correctly); T = 700; label by terminal ellipsoid membership.
3. `generate_quadrotor_2d_trajectories_rl.py`: same, T = 1500, ellipsoid
   centered at the attractor artifact.
4. `generate_quadrotor_3d_trajectories.py`: same, T = 800.
5. `compute_invariant_sets.py`: new, as above.

Env note: `_get_done` in cartpole/quadrotor early-returns on `goal_reached`
without setting `self.out_of_bounds`; when bypassing goal termination, seed
`env.out_of_bounds = False` (or fix the env) to avoid the AttributeError.

### Out of scope

- Noisy pendulum datasets (no invariant set exists under the noise).
- Humanoid dataset (separate repo).
- partial_deterministic derivatives (rebuilt downstream once the new base
  datasets exist).
